# 단어 학습 경험 설계·검증 계획

작성일: 2026-10-30 · 상태: 조사·계획 및 첫 구현 완료, 실제 사용자 검증은 예정

아래 코드 관찰은 변경 전 `1bc0d5b` 기준이다. 본 문서는 조사·실험 계획을 보존한다. 사용자 요청에 따라 기본 B 흐름과 선택적 음성을 먼저 구현했으며, 실제 반영 범위와 남은 검증은 [구현 결정](implementation.md)에 정리했다. 구현 완료와 사용자 검증 완료는 별개다.

## 1. 목표와 판단 기준

사용자가 현재 환경에서 적은 조작으로 학습을 시작하고, 중단해도 쉽게 이어가며, 시간이 지난 뒤 목표한 단어의 의미나 표현을 다시 떠올리게 한다.

함께 평가할 세 축은 **조작 부담·사용 맥락 적합성·지연 기억**이다. 앱 체류 시간이나 출석이 늘었다는 이유만으로 성공이라고 판단하지 않는다. 단어 학습 이외에 자료를 읽으러 들어온 목적도 존중한다.

이번에 확인한 근거와 한계는 [조사 노트](evidence.md)에 있다. ‘2번 터치’, ‘5개 한 묶음’, ‘음성으로 자동 진행’은 검증할 후보이며 최적안으로 확정하지 않았다. 기존 페르소나의 가상 인터뷰는 사용자 검증 표본으로 계산하지 않는다.

## 3. 우선순위와 연결한 실패

발생률을 모르므로 정교한 수치 점수를 만들어 우선순위인 것처럼 제시하지 않는다. 현재 요구와 코드에서 직접 연결되는 문제, 다른 기능의 기반이 되는 문제를 먼저 본다.

| 순서 | 다룰 문제 | 근거·가설 | 먼저 검토할 변화 |
|---|---|---|---|
| P0 | 시작과 종료가 불분명함 | E03, E06, 첫 화면 가설 | 분량이 보이는 시작, 묶음 종료, 이어하기 |
| P0 | 무음·한 손·갑작스러운 중단 | 사용자 요구, E07, E10 | 무음으로 완결되는 복습, 명확한 버튼, 상태 보존 |
| P0 | 자기평가와 실제 기억을 혼동 | E11, E12 | 답 확인 방식 비교, 지연 확인과 기록 구분 |
| P0 | 저장이 복습 부담으로 이어짐 | E02, E03, 현재 코드 | 신규 편입 조절, 이번 묶음과 전체 잔량 분리 |
| P1 | 반복 오답으로 지침 | E04 | 쉬운 설명·원문·뜻 분리·보류 경로 |
| P1 | 읽기와 듣기 사이의 목표 차이 | P03 가설, 기존 장면 재생 | 듣기 선택과 자막 공개 시점 검토 |
| P1 | 실제로 표현을 꺼내지 못함 | P02 가설, E09, E10 | 말하기 과제와 인식 오류 회복 |

E 번호는 [조사 노트](evidence.md)의 근거 ID다. P 번호는 [페르소나](../../personas/README.md)의 인물 ID다. P0~P2는 구현 순서의 우선순위다.

## 4. 첫 화면: 상태에 따른 한 가지 주요 행동

| 상태 | 주요 행동 후보 | 가까이 둘 선택지 |
|---|---|---|
| 첫 방문, 저장 단어 없음 | 샘플 3개로 사용법 체험 | 내 자료 추가, 샘플 건너뛰기 |
| 저장은 했지만 아직 익히지 않음 | 저장한 단어 뜻과 예문 짧게 보기 | 바로 기억 확인, 자료로 돌아가기 |
| 복습 예정 항목 있음 | `단어 5개 복습 · 조용히` | 방식 변경, 자료 이어 읽기 |
| 진행 중 묶음 있음 | `남은 2개 이어하기` | 오늘은 마치기 |
| 오래 쉬었다가 복귀 | `3개부터 다시 시작` | 전체 목록, 목표·자료 범위 변경 |
| 이번 묶음 완료 | `여기서 마치기` | 다음 묶음, 읽던 자료 |
| 전체 예정 복습 완료 | 읽던 자료 이어 보기 | 직접 고른 단어 연습 |

3개·5개는 시안에 사용할 값이다. 새 단어·처음 보는 긴 표현·영상 과제에 같은 예상 시간을 붙이지 않는다. 묶음을 끝냈다고 전체를 끝낸 것으로 표시하지 않는다. 사용자가 정한 시험 범위를 길게 이어 푸는 선택도 유지한다.

## 5. 비교할 학습 흐름

### A. 현재 방식에 가까운 사전 자기평가

문제 → `알아요` 또는 답 공개 → 다음 항목. 아는 항목의 조작은 적지만 정답과 비교하지 않는 경우가 생긴다. 현재 구현의 인출 의도는 유지하되 한계를 관찰한다.

### B. 답 확인 후 자기평가

문제 → 속으로 떠올리기 → 답 확인 → `맞혔어요` 또는 `다시 볼래요` → 다음 항목. 정상적인 기본 경로는 문제당 2번 터치이며, 힌트·재생·취소는 별도다. 정답을 본 뒤 ‘원래 알고 있었다’고 판단할 가능성을 함께 검사한다.

### C. 짧은 실제 답 제출

문제 → 짧게 입력하거나 말하기 → 판정과 답 확인. 목표어가 명확한 경우부터 시작한다. 버스에서 기본 입력 방식으로 강제하지 않는다. ‘뜻을 고르는 문제’는 의미 구분 확인에 쓸 수 있지만 자유 회상과 같은 능력을 측정한다고 보지 않는다.

처음에는 A와 B를 비교한다. C는 목표가 표현 생성인 사용자에게 별도 과제로 시험한다. 화면 문구·문항 수·자료·난이도·오답 설명을 동시에 바꿔 어느 변화가 영향을 줬는지 알 수 없게 만들지 않는다.

고정 대기 시간이나 타이머를 두고 정답을 강제로 공개하지 않는다. 빨리 눌렀다는 이유만으로 아는 단어라고 간주하지 않는다. 버튼 위치는 고정하고, 스와이프는 선택적 보조 조작으로만 검토한다.

## 6. 상황별 경로와 실패 회복

| 상황 | 제공할 경로 | 반드시 확인할 실패 회복 |
|---|---|---|
| 버스, 소리·발화 불가 | 글자·속으로 떠올리기·큰 버튼 | 마이크·오디오 요청 없이 끝까지 가능 |
| 이어폰, 발화 불가 | 듣고 떠올리기·터치 응답 | 다시 듣기와 자막 확인, 언제든 무음으로 전환 |
| 집, 발화 가능 | 뜻·상황 보고 영어로 응답 | 인식 텍스트 확인, 다시 말하기 또는 터치로 전환 |
| 한 손 사용 | 엄지 영역의 일정한 버튼 | 실수 평가를 복잡한 설정 없이 되돌리기 |
| 전화·하차·앱 전환 | 세션 일시정지 | 무응답을 오답으로 만들지 않고 미완료 카드 복원 |
| 접속 불안정 | 이미 표시된 내용을 유지 | 저장 실패를 완료로 표시하지 않고 중복 기록 없이 재시도 |
| 영상 삭제·재생 실패 | 텍스트·저장 문장 | 카드 전체가 막히지 않음 |
| 마이크 거부·STT 미지원 | 무음 학습 | 오류를 학습 실패로 기록하지 않음 |
| 장기 미접속 | 작은 복귀 묶음 | 기록을 초기화하지 않고 잔량을 확인 가능 |
| 뜻 여러 개·전문 용어 | 출처의 뜻을 명시한 문제 | 다른 타당한 뜻을 무조건 오답으로 처리하지 않음 |
| 아주 짧은 여유 시간 | 한 항목만 끝내고 종료 가능 | 약속한 묶음을 다 끝내지 않아도 처리 결과 유지 |
| 글자 확대·음성 사용 곤란 | 텍스트와 버튼으로 동일 과제 | 색·소리·숨은 제스처만으로 의미를 전달하지 않음 |

버스·한 손·중단은 P02/P04 관점, 듣기는 P03, 시험 범위는 P01, 출처와 의미는 P05 관점으로 우선 점검한다. 실제 조사 참여자를 이 가상 인물에 억지로 맞추지 않는다.

## 7. STT·TTS를 붙일 때의 원칙

1. 처음에는 무음으로 시작한다. 마지막 방식은 기억할 수 있지만 `듣기 시작`·`말하기 시작`이라는 명시적인 행동 뒤에 오디오·마이크 세션을 시작한다.
2. 출력과 입력을 분리한다. 듣기만 가능한 사람에게 말하기를 요구하지 않는다. 의미 확인 과제와 표현 생성 과제의 결과도 구분한다.
3. 연속 음성 모드에서도 침묵을 자동 오답으로 처리하지 않는다. 인식 대기가 길어지면 다시 시도·정답 확인·터치로 전환할 수 있게 한다.
4. TTS 재생 중에는 마이크가 정답을 다시 듣고 사용자의 답으로 기록하지 않도록 순서를 검증한다. 오디오가 정답을 읽은 뒤의 따라 말하기는 독립 회상으로 기록하지 않는다.
5. 인식된 답과 학습 판정을 구분한다. 발음 점수는 STT 문자열로 만들지 않는다. `postpone`을 목표로 물었는데 타당한 대안 `delay`를 말했다면 문장 의미의 적절함과 목표 단어 회상 여부를 구분한다.
6. 확신할 수 없는 판정은 학습자 오답으로 확정하지 않는다. 되돌리기와 자기평가 전환 결과는 그 출처를 남긴다.
7. 음성 오류·지연·기기별 사용 가능성을 먼저 검증한 뒤 자동 진행을 확대한다. 마이크 시작·정지 상태가 화면에서 보여야 한다.

오디오 경로 변경·백그라운드 전환 시 정지 동작은 실제 지원 기기에서 점검한다. 브라우저가 제공하지 않는 이어폰 분리 감지를 가능하다고 가정하지 않는다. 단말 네이티브 기능이나 완전 오프라인 지원은 이번 기본 시안의 전제로 삼지 않는다.

## 8. 복습량과 카드 품질 관리

- **저장과 학습 편입:** 저장은 빠르게 유지한다. 모든 저장을 즉시 과제로 만드는 방식과, 기본 분량 안에서 순차 편입하고 참고용으로 남길 수 있는 방식을 비교한다. 저장할 때마다 설정 모달을 띄우지 않는다.
- **복귀:** 전체 잔량은 그대로 두고 작은 묶음을 제안한다. 필요한 경우 신규 편입을 줄이거나 잠시 멈출 수 있게 한다. 매일 처리하는 양보다 들어오는 복습이 많으면 잔량이 줄지 않는다는 점을 숨기지 않는다.
- **반복 오답:** 같은 문제를 더 자주 내는 것에 더해 설명·문맥·한 카드의 정보량을 점검한다. 수정·보류·참고용 전환을 사용자가 선택할 수 있게 한다.
- **세션 재시도:** 초기 후보는 기본 5개와 추가 재시도 최대 2개다. 시작 전에 추가 확인 가능성을 알려주고 기본 묶음 종료 시 끝낼 수 있게 한다. ‘5개’라고 약속한 뒤 끝없이 늘리지 않는다. 이 수치는 검증 전 가정이다.
- **일정 계산:** 같은 세션에서 답을 본 뒤 다시 맞혔다고 다음 복습일을 여러 차례 연장하지 않는다. 재학습과 다음 날짜의 독립 회상을 별도로 처리할 수 있는 기록이 필요하다.

## 9. 단계별 실행 계획

| 단계 | 작업 | 산출물 | 다음 단계로 갈 조건 | 현재 상태 |

## 10. 검증 실험

### 실험 1: 시작과 복귀 사용성

- 탐색용 첫 표본: 10명. 최근 중단자 4명, 간헐·지속 사용자 4명, 가입·설정 중 포기한 사람 2명을 목표로 모집한다. 수치는 조사 운영안이며 통계적 대표성을 뜻하지 않는다.
- 버스처럼 소리를 못 쓰는 조건, 집, 30초 뒤 중단, 복습 누적 상태를 포함한다. 위험한 실제 이동 중 실험 대신 앉은 상태에서 환경을 재현한다.
- 현재 홈과 작은 묶음 홈의 제시 순서를 교차 배정한다. 자신이 하려던 일을 먼저 묻고 과제를 수행하게 한다.
- 기록: 첫 의미 있는 행동까지 시간, 필요한 터치, 되돌아감, 도움 요청, 묶음과 전체 완료의 혼동, 중단 후 복원 성공.
- 잠정 진행 조건: 10명 중 8명 이상이 설명 없이 시작·중단·복귀를 수행하고, 예상하지 않은 소리·기록 손실·완료 오표시는 관찰 과제에서 0건. 보편적 합격 기준이 아니라 이번 시안의 수정 기준이며, 작은 표본에서 0건이라고 실제 오류율이 0인 것은 아니다.

### 실험 2: 사전 자기평가와 답 확인 후 자기평가

- 별도 탐색 파일럿 12~20명을 운영안으로 둔다. A와 B의 단어 수·제시 형식·반복 기회를 맞추고 학습 방식의 제시 순서와 어휘 목록을 교차 배정한다.
- 사전 확인으로 이미 아는 항목을 제외하고 난이도가 비슷한 목록을 나눈다. 학습 시간은 실제 소요를 기록한다. 동일 분량의 결과와 시간당 결과를 함께 비교하며 둘을 혼동하지 않는다.
- 지연 검사에서는 자기평가 버튼 대신 짧은 답 제출과 사전에 정한 허용 답안 기준을 사용한다. 가능하면 채점자는 학습 조건을 모르게 한다. 전문 용어는 문맥의 뜻을 기준으로 검토한다.
- 24시간과 7일 검사는 서로 다른 항목 집합을 사용한다. 앞선 검사가 뒤 검사 항목의 추가 학습이 되지 않게 하기 위해서다. 두 집합은 조건별로 균형 배정하며 중간 노출은 기록한다.
- 단어 뜻 회상·표현 생성·듣기 이해를 합산한 한 점수를 만들지 않는다. 집 밖에서 말하기 어려운 참가자에게 음성 응답을 강제하지 않는다.
- 다음 날·7일째 참여하지 않은 사람은 실제 오답과 구분해 누락으로 기록한다. 응답자만의 기억률과 추적 응답률을 함께 보고하고, 누락을 실패로 간주한 보수적 분석도 별도 제시한다.
- 판단: B가 조작 부담을 수용 가능한 수준으로 유지하면서 지연 기억에서 개선 가능성을 보이는지, 자기평가 과신이 커지는지 본다. 작은 표본의 비유의 결과를 ‘동등함’으로 판정하지 않는다. 확증 비교의 표본 수와 허용 차이는 파일럿 변동성과 제품 기준을 바탕으로 사전 결정한다.

### 실험 3: 음성이 필요한 사람에게 실제로 도움이 되는가

- 듣기 목표와 표현 생성 목표를 구분해 참가자를 선정한다. 무음과 음성 과제를 무작정 전체 사용자 평균으로 비교하지 않는다.
- 지원 대상 브라우저·단말, 조용한 방·생활 소음, 짧은 단어·문장을 점검한다. 회상 답변을 위한 충분한 대기와 언제든 터치로 넘어가는 경로를 포함한다.
- 참여자의 실제 답을 기준으로 인식 텍스트가 맞는지, 학습 판정이 맞는지 따로 검토한다. 정답으로 인식된 비율만으로 발음 향상이나 기억 향상을 주장하지 않는다.
- 음성 인식 실패가 자동 오답으로 기록되거나 TTS가 자기 답으로 들어오면 자동 진행 확대를 중단하고 수정한다.

## 11. 기록과 지표

| 질문 | 지표·기록 방식 | 오해하지 말 것 |
|---|---|---|
| 시작이 쉬워졌나 | 복습 의도가 있는 진입 중 첫 회상 시도 비율, 그때까지 조작 수·시간 | 읽으러 온 방문을 모두 실패 분모에 넣지 않음 |
| 부담이 줄었나 | 선택한 묶음 완료, 중단 사유, 다시 시작까지의 단계 | 짧게 정상 종료한 것을 이탈로 보지 않음 |
| 실제로 기억하나 | 24시간·7일의 힌트 없는 답, 새 문맥의 의미 구분 | 당일 재시도·자기평가와 분리 |
| 시간 대비 가치가 있나 | 지연 확인된 항목 수와 실제 학습 시간 | 더 많은 클릭·더 긴 체류를 학습 효과로 간주하지 않음 |
| 누적이 관리되나 | 예정 항목 잔량, 신규 편입, 완료량, 보류량의 변화 | 화면에 적게 보여주는 것만으로 누적 해결이라 하지 않음 |
| 복귀가 가능한가 | 복귀 의사를 가진 사람의 첫 묶음 시작·완료·다음 이용 | 목표를 끝내고 쉬는 사람을 무조건 실패로 분류하지 않음 |
| 음성을 믿을 수 있나 | 인식 오류와 채점 오류, 수정·터치 전환 성공 | 기술 오류와 모르는 답을 분리 |

계획하는 최소 기록은 세션·항목·시도 ID, 학습 목표, 표시 방식, 응답 방식, 힌트·정답 노출, 평가 출처, 결과, 중단·재개, 제시·응답 시점이다. 결과는 정답·오답 외에 건너뜀·중단·기술 실패·판정 미확정을 구별해야 한다. 자기평가, 실제 답 채점, 같은 세션 재시도, 지연 검사를 구별해 집계한다.

운영 지표를 위해 원문 음성이나 개인 학습 자료 전체를 기본 수집할 필요는 없다. 음성 오류를 사람이 점검하는 파일럿에서는 참가자가 동의한 표본만 별도 취급한다. 현재의 일별 카운트만으로 위 지표가 이미 측정된다고 가정하지 않는다.
