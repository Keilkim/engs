# 2026-11-11 · 밑줄 파선 다듬기, 자리 표기, 북마크 여백

- 기존 공개 저장소 `Keilkim/engs`의 `main`에 반영하고, Vercel 자동 배포(<https://engs-red.vercel.app>)로 내보낸다.
- 저장된 표현 밑줄을 1.2px로 얇게 하고, 선 7px·간격 4px로 바꿔 점선이 아닌 파선으로 보이게 했다. 색 구분(고정 진한 파랑, 자리 옅은 파랑)은 그대로다.
- 옅은 파랑 밑줄(바뀔 수 있는 자리) 바로 아래에 그 자리를 패턴에 쓰인 표기 그대로 작게 쓴다. 예: `take A into account`의 `A`, `to-v`의 `v`, `be used to V-ing`의 `V-ing`, `who + 동사`의 `동사`. 글자는 그 줄 글자 크기에 맞춰 커지고 작아진다. 문법 팝업에서도 각 패턴 아래에 문장 속 조각을 같은 파선과 표기로 보여 준다.
- 표기도 목록으로 판정하지 않는다. 새 분석은 AI가 자리마다 `label`을 주고, 저장 시 그 표기가 패턴 형태 안에 실제로 있을 때만 쓴다. 표기가 없는 기존 저장분은 템플릿과 문장을 맞춘 정렬에서 그 자리에 쓰인 템플릿 글자를 가져온다. 한 구간에 자리가 둘이면(`give A B`) 각 자리가 맡은 부분만 쓴다.
- AI가 표현 자신의 단어(활용형 포함, `was`↔`be`, `told`↔`tell`)를 자리로 잘못 표시하면 고정으로 바로잡는다. 표기와 철자가 같은 자리(`make A do`의 `do`)는 그대로 자리로 둔다. 축약형 일부(`isn't`의 `n't`)로 나뉜 조각도 제자리에 놓는다.
- 북마크한 자료를 다시 열면 북마크 선이 화면 맨 위가 아니라 위에서 1/5 지점에 오도록 해 그 위 내용이 보이게 했다. 저장 위치는 바뀌지 않는다.
- 역할·표기 계산은 페이지와 팝업이 함께 쓰는 `src/utils/grammarRoles.js`로, 프롬프트와 저장 검증은 `src/services/ai/grammarPrompt.js`로 모았다. 스키마·인증·환경 변수 변경은 없다. `label`은 기존 JSON에 추가되는 필드라 직전 배포로 코드 복구가 가능하다.

## 전 유형 검증 (실제 Gemini)

- `scripts/eval-grammar-segments.mjs`가 운영과 같은 프롬프트·요청 설정·저장 검증으로 22개 유형 104문장(`scripts/grammar-eval-corpus.json`: 관용구, 분리형/비분리 구동사, to부정사, 동명사, 분사, 관계절, 가정법, 수동태, 완료·진행, 조동사, 비교, 상관접속사, so/too, 사역·지각, 가주어·강조, 도치, 부사절, 명사절, 축약형, 숙어)을 운영 모델 `gemini-3.8-flash`와 2027-01-01 전환 모델 `gemini-3.5-flash-lite`로 돌렸다. 고객 자료는 쓰지 않았다.
- 패턴마다 기계 판정: 조각이 문장에 글자 그대로 있는가, 문장에 순서대로 놓이는가, 모든 자리에 표기가 붙는가, AI 표기가 패턴 형태 안에 있는가. 별도로 역할을 지우고 템플릿 정렬로 다시 계산해 단어별 일치율을 쟀다.
- 최종 수치: `gemini-3.8-flash` 202개 패턴 전부 모든 판정 통과(100%), 정렬 일치율 97.0%. `gemini-3.5-flash-lite` 163개 중 97.5% 통과, 일치율 93.6%. lite의 실패 4건은 패턴 형태에 없는 표기를 지어내거나 조각을 문장과 다르게 옮긴 경우로, 해당 자리는 표기 없이 밑줄만 그리거나 조각이 빠진다(오류 표시는 없음). 첫 실행에서 나온 실패(축약형 안 조각 배치, 형태에 없는 자리, 활용형을 자리로 표시)는 원인 유형 단위로 고친 뒤 다시 돌렸다.
- 남은 불일치는 대부분 템플릿이 전부 기호인 패턴(`명사 + V-ing`)에서 정렬이 기준 단어를 찾지 못하는 경우로, 새 분석은 AI가 역할을 직접 주므로 해당하지 않는다.
