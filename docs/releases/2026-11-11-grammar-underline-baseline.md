# 2026-11-11 · 문법 밑줄 기준선·파선·역할 구분

- 기존 공개 저장소 `Keilkim/engs`의 `main`에 반영하고, Vercel 자동 배포(<https://engs-red.vercel.app>)로 내보낸다.
- PDF·이미지·웹 캡처의 저장된 표현 밑줄은 한 줄마다 a·b·c 같은 글자의 기준선에 긋는다. OCR 상자가 g·p·y 꼬리까지 감싸서 단어마다 밑줄 높이가 달라지던 문제를 고쳤다. 꼬리 글자는 일반 밑줄처럼 선이 꼬리를 지나간다. 줄은 읽는 순서로 나눈다. 기준선은 꼬리 없는 단어들로 기울기까지 맞추므로 살짝 기운 스캔에서도 줄이 섞이지 않는다. 떨어진 대시·따옴표·위 첨자는 같은 줄에 붙고 기준선 계산에는 쓰지 않는다. 꼬리 글자만 있는 줄은 같은 단(칼럼)의 이웃 단어에서만 기준선을 빌린다.
- 밑줄은 모두 파선이다. 표현에 고정된 단어(`to`-v의 `to`, `take … into account`)는 진한 파랑, 바뀔 수 있는 자리를 채운 단어(A·B·~, to부정사의 동사 등)는 옅은 파랑이다. 앞 릴리스의 "진한 실선/연한 실선" 표기를 대체한다.
- 고정/대체 구분은 표기 목록으로 판정하지 않는다. 새 분석은 AI가 문장 순서대로 `segments`(`fixed`/`slot`)를 돌려주고, 저장 시 문장에 실제로 있는 조각만 남긴다. 플래시카드·복습이 읽는 `spans`/`variableSpans`는 여기서 만든다. 고정 조각이 없는 패턴은 대체 조각을 `spans`로 써서 카드 강조가 비지 않게 한다.
- 역할 정보가 없는 기존 저장분은 템플릿 단어를 문장 단어와 순서대로 최대한 맞춰 역할을 복원한다. 맞춘 단어는 고정, 저장 범위 안이나 고정 단어 사이에서 맞지 않은 단어는 대체로 본다. 매칭은 활용형(be↔am, ask↔asked), 문맥 속 축약형(isn't, It's, She's)을 인식한다. 템플릿 단어는 짝이 없어도 넘어갈 수 있어 `look/watch`, `in (the) case of`, 분리형 구동사(`pick it up`)도 맞는다. 전부 대문자인 템플릿 단어(A, B, V, SB)는 문장에서 같은 철자일 때만 단어로 본다. 반복 단서(as … as, the more … the more)는 같은 절 안에서 함께 찾는다. 템플릿에 문장 단어가 하나도 없으면(예: `현재완료`) 저장된 단서를 고정으로 둔다. 대체 단어가 저장되지 않았거나 어느 위치인지 구분할 정보가 없으면 추측하지 않는다.
- 새 분석의 조각은 순서대로 가장 가까이 모인 한 곳에만 표시하므로 같은 문장의 다른 `to`에는 밑줄이 없다.
- 스키마·인증·환경 변수·암호화 변경은 없다. `segments`는 기존 JSON에 추가되는 필드라 직전 배포로 코드 복구가 가능하다.
